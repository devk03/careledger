# Encrypted draft-pair preflight — fictional-only status

The unmounted `SqliteDraftPairReservation` service uses the already-approved managed v10 schema. It does not create or apply migrations, expose an HTTP route, inspect plaintext, accept files or publish a care day. It accepts only a private, already-opened managed SQLite connection and rechecks session, CSRF, bound device, current draft key, contribution grant, schema and durable journal settings inside each immediate transaction.

The device first requests one reservation and receives two intent IDs and two blob IDs. It encrypts content and metadata under its draft key using those reserved blob IDs, keeping filenames, care dates and note text inside ciphertext. It then supplies only opaque object IDs and plaintext byte counts to bind both role-specific intents in one transaction. A later call opens both staging leases in one transaction after checking family and global logical-wire quotas. One partial intent or lease cannot be returned by this service. A reservation is tied to the exact session and device and expires after ten minutes; a current-key change invalidates it.

Guarded acceptance used a private copy of the exact previously approved empty fictional v10 database, two independently seeded fictional families and browser AES-GCM v2 encryption. It passed cross-family and valid second-session denial, wrong CSRF, device/session revocation, key rotation, quota denial, collision rollback and an eight-reservation burst cap. Two independent SQLite worker connections also contested a global cap for exactly one additional pair: one received both leases, the other none. This establishes the quota outcome, not proof that both calls were simultaneously blocked on SQLite's held writer lock. The source DB checksum is pinned in `server/test/managedFictionalDraftPair.mjs`; the test never migrates or changes that source. The full server TypeScript suite is separate from this guarded test.

This is **not ready to mount**. The v10 occupancy view permanently counts an uncommitted lease even after its intent expires, and immutable reservation/ID-claim rows also accumulate. The burst caps slow misuse but do not reclaim storage or quota. A separate [unmounted fictional non-day HTTP slice](managed-non-day-upload-slice.md) now commits both draft-role ciphertexts and reads exact receipts through the existing v10 schema, but it does not resolve that lifecycle gap or publish the pair. Before any public write path, obtain separate approval for the [forward-only lifecycle proposal](managed-lease-lifecycle-proposal.md) and implement storage-verified reconciliation; test interruption, orphaned objects, safe retry, stronger lock-contention evidence and expiry. Then complete non-day read grants, signed pending-pair publication and adult review. No real records or production database may use this slice.
