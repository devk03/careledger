# Structural-parser boundary (protocol only)

This is the protocol for a dedicated parser helper in the private TypeScript pilot. `server/src/ingest/parserProtocol.ts` defines the request/reply contract, `server/src/ingest/parserSocket.ts` implements its bounded Unix-socket client, and `server/src/ingest/parserWorker.ts` provides a development worker with a dedicated `runParserWorker.ts` entrypoint. It independently hashes exact request bytes and decodes JPEG/PNG, but rejects PDFs. The worker refuses UID 0, binds only an absolute Unix socket under a restrictive umask in a private worker-owned parent, and verifies the socket mode is `0660`. Its group must contain only explicitly trusted app/worker principals. **No OS-isolated parser deployment or upload route exists yet.** A worker passing synthetic tests is not permission to ingest medical files.

The TypeScript server remains the only database writer. After admission and malware scanning, it will send one bounded file per request to a trusted local Unix socket. The request is a four-byte big-endian JSON-header length (at most 512 bytes), that exact UTF-8 JSON header, and exactly `byteSize` binary file bytes (at most 30 MiB). The client then half-closes its write side; the worker must wait for end-of-input and reject any excess or missing bytes before replying. The worker will reply with a four-byte big-endian JSON length and at most 2,048 bytes of strict UTF-8 JSON, then close the connection. Both sides must reject incomplete, excess, or mismatched framing. The binary payload is the full document and can contain identifying text; the JSON metadata must not contain filenames, document text, arbitrary parser errors, or user-provided shell arguments.

The header binds a random request ID, media type, SHA-256, byte size, protocol version, and policy version. A reply must echo those fields exactly and carry the expected pinned worker version. **Echoing the digest is not proof of inspection:** the worker must read exactly `byteSize` binary bytes, independently hash them, compare the result to the header digest, and only then return `safe`; the server must send bytes verified against the staged original. A safe PDF reply must report page/object counts and maximum page dimensions within pilot limits and explicitly assert no encryption or active content. A safe JPEG/PNG reply must report one frame, one page, and bounded pixel dimensions. A rejection carries only a fixed code. Timeouts, crashes, malformed or oversized replies, unsupported fields, version drift, and unavailable workers fail closed.

The helper must decode and inspect the *entire* file with mature format libraries; PNG preflight and PDF byte-marker searches are insufficient. `Dockerfile.parser` builds a dedicated non-root Debian/Node image from a minimal `parser/` lockfile containing Sharp and Zod, not the server's database dependencies. Executable code and dependencies remain root-owned/readable by the worker, not worker-writable. `compose.parser.yaml` is an opt-in **synthetic-data sandbox preview** with no network or ports, read-only rootFS, a socket-only volume, and explicit memory/CPU/PID limits; it does not modify the existing app deployment. The application must not have control of a Docker daemon or general container-launch socket. The helper should have no database or object-store access. Transport authentication, isolation, and the absence of sensitive text in worker-supplied metadata are trusted-worker/deployment properties, not guarantees made by the JSON schema. Raw replies must not be logged.

The adapter rejects early, mismatched, truncated, excess, timed-out, and unavailable replies. The development worker waits for request EOF, independently hashes exact payload bytes, rejects excess or missing bytes, and launches each JPEG/PNG decode in a short-lived child process using a pinned Sharp/libvips dependency. The socket server can SIGKILL that child on deadline or observable disconnect; tests include a deliberately stalled child. The socket server's own in-process timer is still not a hard wall-clock guarantee if its event loop blocks. After request half-close, client disappearance may be unobservable until a write, so the child deadline is essential. This is not called by Express. A constrained worker runtime with memory/CPU limits, an external service watchdog/restart policy, PDF inspection, and synthetic tests for malformed/active/encrypted PDFs, excessive pages/objects/geometry, animation, decompression bombs, and staged-byte replacement remain. Do not wire this into `inspectStagedOriginal` or a user-facing upload route until those tests and the sandboxed deployment pass review.
