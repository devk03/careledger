# Non-day draft ciphertext upload — unmounted fictional test

The managed-v10 `SqliteNonDayDraftUploadLedger` consumes the two leases that `SqliteDraftPairReservation` opened atomically. It does not issue intents or open another lease. Through the existing staged-upload adapter, the server stages create-only ciphertext chunks in a private directory, re-reads their exact v2 wire hash/length, then rechecks session, CSRF, bound device, current contribution grant, draft scope/key, reservation, lease, logical quota and one-use state inside `BEGIN IMMEDIATE`. Nonce reservations, chunk references and one committed-blob row enter the same transaction. The read-only receipt operation returns only `unconfirmed` or the committed ciphertext hash and length to a currently authorized, device-bound account. Neither method sees plaintext or approves a care day.

The guarded [fictional HTTP test](../server/test/managedFictionalNonDayHttpUpload.mjs) copies only the separately approved empty v10 database after verifying its private temporary location and exact SHA-256. It invents two families and ciphertext. In its isolated Express app, the browser-like caller requests a reservation, encrypts under the returned blob IDs, then binds both intents and opens both leases through the unmounted draft router before uploading. Both draft roles then pass through the real parser, private object store, wire proof and ledger; exact receipts survive a second SQLite connection. Cross-family upload/receipt, wrong Origin/CSRF, malformed wire and device revocation fail. A reused nonce after disk staging returns a conflict with zero new nonce/chunk/committed rows; its failed lease remains charged and the staged object may be orphaned. The test checks that its fictional plaintext marker is absent from the database files and referenced ciphertext objects. It does not inspect logs, backups or every orphan. On 2026-09-27 it passed again using the newly approved empty local v10 database; the older temporary source remained present and was not modified or used.

Run only against the exact approved disposable fictional source, never a production or case database:

```sh
npm --prefix server run build
cd server
ADENO_APPROVED_FICTIONAL_MIGRATION=1 node_modules/.bin/vite-node test/managedFictionalNonDayHttpUpload.mjs /absolute/path/from-the-separately-approved-runner/managed.sqlite3
```

This is **not a mounted production path**. The test uses structural fictional enrollment/grant rows, not independently verified real owner signatures or an actual browser UI. It commits content and metadata separately, then submits a genuinely signed pending pair through an unmounted same-origin route and transactional writer in the isolated fictional DB. A second invented note uses the real client-side draft preparer, purpose-bound key envelope, committed receipts and browser signer code through that same route under Vite's Node test runner. A separate [real-Chromium HTTP proof](managed-browser-draft-pair-http.md) now exercises browser WebCrypto, cookie, CSRF, fetch, journal, exact receipts and signature against a test-only same-origin server. It is scripted browser code, not the product UI. Neither proof publishes or approves a care day or provides a public route. V10 lacks database-enforced session-device binding on non-day writes; the adapter checks it in application code, but direct writers could bypass that. An existing lease can be opened by more than one concurrent request, leaving extra private objects even though only one commit wins. Failed/expired leases cannot be safely released, so logical quota can remain charged forever; physical orphan, WAL and backup bytes are outside that quota. Public use still needs separately approved lifecycle and binding migrations, reconciled crash/ambiguous-commit behavior, a unified day/non-day intent dispatcher, bounded physical storage, payload retention for signature audit, actual browser UI integration, client-side PDF safety and independent security review. No new migration was created or applied for this slice.
