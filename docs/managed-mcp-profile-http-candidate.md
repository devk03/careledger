# Fictional local MCP connection-profile transport

This is an **unmounted fictional-test, localhost-only** Streamable HTTP proof using the pinned MCP TypeScript SDK v2 and Node adapter. Construction requires the test-process marker, and every request requires loopback local and peer sockets. It registers only `get_connection_profile`, whose result is a short opaque account handle, the `mcp:profile` scope, and `private_records_available: false`. It does not import the existing timeline/source-page MCP factory, decrypt records, expose a family/patient name, or enable an agent to read health content.

The isolated Express router checks its configured exact Host and any supplied Origin, requires one bearer header and no cookie, applies an injected limiter, and asks an injected verifier for a fresh adult-approved grant on **every** request. It requires the same subject to have approved the grant, active adult membership, the exact `/mcp` audience and single profile scope, and a short live expiry before invoking the SDK. Fictional HTTP tests use the real MCP client transport to initialize, list the one tool and call it; they also deny missing, revoked, expired, wrong-audience, wrong-scope, child, cross-origin and wrong-host requests. The current web/public-shell apps still do not mount `/mcp`.

This is not OAuth or production authentication. The fictional verifier is in-memory test state; no durable consent, token issuer, protected-resource discovery, authorization-code/PKCE flow, shared revocation, real adult approval screen, trusted proxy configuration or device-held E2EE sharing exists. A `401` here is a local test challenge, not a working sign-in link. Do not deploy or point a caregiver's agent at this candidate. The [MCP product contract](mcp-first-product.md) and [managed launch gates](managed-launch-gates.md) remain controlling.
